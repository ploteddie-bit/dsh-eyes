# DSH Eyes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Un démon Rust + extension Chrome qui donne au harnais DSH des yeux dans le navigateur : volumes par domaine, détection d'appels à localhost par les agents IA, journal persistant, API HTTP locale.

**Architecture:** Extension Chrome MV3 (JS obligatoire — seule techno exécutable par Chrome) qui observe la navigation via `chrome.webRequest` et pousse chaque requête sur un WebSocket local. Le démon Rust (`tokio` + `axum` + `tokio-tungstenite`) reçoit, agrège les compteurs par domaine, applique les règles du vigil (127.0.0.1, domaines inconnus), persiste en JSONL et expose `/stats`, `/events`, `/health` sur `127.0.0.1:8445`.

**Tech Stack:** Rust stable, tokio, axum, tokio-tungstenite, serde/serde_json, Chrome Extension Manifest V3. Cible de build : `x86_64-unknown-linux-musl` (binaire statique, WSL Ubuntu).

## Global Constraints

- **Standard qualité : `dev-rust`** (skill `Edy:~/.dsh/skills/dev-rust`) — non négociable : zéro `unwrap()/expect()` en async/réseau, compilation vérifiée avant tout, `cargo clippy -- -D warnings` vert, `Cargo.lock` versionné.
- Le démon n'écoute **que** sur `127.0.0.1:8445` — jamais `0.0.0.0`.
- Aucune donnée de navigation ne quitte la machine : tout reste local (fichiers dans `~/.dsh-eyes/`).
- L'extension ne capture **que** les métadonnées (URL, domaine, horodatage, taille si dispo) — jamais le contenu des pages.
- Répertoire du projet : `Edy:~/projets/dsh-eyes/` (repo git neuf, branche `main`).
- Le port 8445 est libre (MESURÉ le 05/10 : aucun service dessus).

#[derive(Serialize)]

pub async fn health() -> Json<Health> {
    Json(Health { ok: true, version: env!("CARGO_PKG_VERSION") })
}

pub fn router() -> Router {
    Router::new().route("/health", get(health))
}

### Task 4: Vigil — règles d'alerte (127.0.0.1, domaines inconnus)

**Files:**
- Create: `Edy:~/projets/dsh-eyes/src/vigil.rs`
- Modify: `src/ingest.rs` (appeler vigil sur chaque événement), `src/api.rs` (route `/events` — dernières alertes)

**Interfaces:**
- Produces: `vigil::check(&NavEvent) -> Option<Alert>` ; `Alert` sérialisé `{"level":"critical","rule":"localhost_access","detail":...}` ;
  `GET /events` → 50 dernières alertes ; les alertes `critical` sont aussi écrites dans `~/.dsh-eyes/alerts.jsonl`.

**Règles v1 :**

1. `localhost_access` (critical) : `domain` = `127.0.0.1`, `localhost`, ou toute IP de `127.0.0.0/8`, `::1`
2. `private_network` (warning) : `10.0.0.0/8`, `192.168.0.0/16`, `172.16.0.0/12`
3. `new_domain` (info) : première occurrence d'un domaine dans la session (les domaines connus sont listés dans `~/.dsh-eyes/allowlist.json`, éditable à la main)

- [ ] **Step 1: Tests unitaires purs** (pas de WS) : `vigil::check` sur 6 cas (localhost v4, localhost v6, 10.0.0.x, domaine allowlisté, domaine neuf, domaine récurrent) — assert exact sur le niveau attendu ou `None`.

- [ ] **Step 2: Implémenter `vigil.rs`** — parsing d'IP sans dépendance lourde : `std::net::IpAddr` + `octets()` suffit pour les plages privées/loopback.

**Files:**

- Create: `Edy:~/projets/dsh-eyes/extension/README.md` (procédure d'installation chrome://extensions → Mode développeur → Charger l'extension non empaquetée)

**Interfaces:**
- Consumes: `ws://127.0.0.1:8445/ws` (Task 2)
- Produces: pour chaque requête web observée, un message JSON au format Task 2.

- [ ] **Step 1: manifest.json**

```json
{
  "manifest_version": 3,
  "name": "DSH Eyes",
  "version": "0.1.0",
  "description": "Vigil de navigation pour le harnais DSH — métadonnées locales uniquement",
  "permissions": ["webRequest", "storage"],
  "host_permissions": ["<all_urls>"],
  "background": { "service_worker": "background.js" }
}
```

- [ ] **Step 2: background.js** — service worker :

  - `chrome.webRequest.onCompleted` (urls `<all_urls>`) → extrait `new URL(details.url).host`, taille via `details.statusCode`/headers content-length si présent
  - reconnexion WebSocket automatique (backoff 1s → 30s) vers `ws://127.0.0.1:8445/ws`
  - file d'attente mémoire si le démon est down (max 1000 événements, FIFO — perte assumée au-delà, loggée dans la console du worker)
  - **aucune** capture de contenu de page, aucun envoi hors localhost

- [ ] **Step 3: Test manuel** — charger l'extension, visiter 3 sites, vérifier `curl /stats` et que les domaines apparaissent.
